# llm-quick-bench · Дом-3D

Быстрый комплексный бенчмарк для новых LLM. Модель проектирует и строит двухэтажный дом из 3D-примитивов, исправляет свои ошибки по отчёту валидатора и перестраивает дом под изменённое ТЗ. На выходе получается **видео (GIF/MP4)** со стройкой, облётом, разрезом и профилем способностей. По такому ролику за 20 секунд складывается короткое, но показательное мнение о модели.

### Первый прогон: Claude Opus 5.5 — 100%

Opus 5.5 с первой попытки прошёл все 27 базовых проверок и 8 проверок гаража, а также визуальный тест. Из неявных требований модель вывела:
- вход с севера, со стороны улицы;
- пологий пандус 1:21 с площадкой и поручнями;
- большое остекление на юг;
- проём в перекрытии над лестницей.

При пристройке гаража модель сама перенесла пандус на запад, чтобы освободить въезд. Самокоррекция не измерена: исправлять было нечего.

Для моделей этого уровня задача уже упирается в потолок. Нужна сложная версия ТЗ.

Как шёл прогон:
- **Ручной режим.** Модель отвечала как отдельный субагент без инструментов: видела только текст задания, код проверок ей был недоступен. В визуальном тесте она открыла только две картинки.
- **Правки валидатора.** По ходу прогона уточнены две проверки гаража. G6 теперь проверяет и свободный проезд от ворот к улице, а площадка внутри гаража больше не считается ошибкой. G8 считает сохранность только по самому дому: вынужденный перенос пандуса не штрафуется.

## Почему дом

Одна связная задача проверяет сразу много способностей, и проверяет их объективно: каждое требование ТЗ можно измерить по геометрии сцены.

| Способность | Что проверяется |
|---|---|
| Формат | строгий JSON, корректная схема ~100–300 объектов |
| Следование ТЗ | габариты, отметки этажей, крыша, балкон, цвета |
| Пространство | замкнутые стены, окна в плоскостях фасадов, ориентация по сторонам света |
| Математика | лестница по нормам (подъём/проступь), уклоны, высоты |
| **Неявные выводы** | требования, которые не названы прямо, а следуют из контекста и норм; это главный «AGI-маркер» |
| Физика | ничего не висит в воздухе, труба проходит сквозь кровлю, ограждения |
| План ↔ дело | совпадает ли то, что модель заявила в `plan`, с тем, что она построила |
| Адаптация | пристройка гаража без регрессий в уже построенном |
| Самокоррекция | какую долю ошибок модель исправляет по отчёту валидатора |
| Зрение | *(опционально)* подсчёт окон и поиск отличий на рендерах |

Итог — среднее по способностям. Всего 27 базовых проверок, 8 проверок для гаража и визуальный тест. Ни один бенчмарк не измеряет AGI напрямую. Этот проверяет признаки обобщения: вывод неявных требований, перенос норм из реального мира, согласованность плана и исполнения, работу с обратной связью и устойчивость к изменениям.

## Фазы прогона

1. **Постройка.** ТЗ из 14 пунктов, ответ — JSON-сцена (`box`, `cylinder`, `sphere`, `wedge`, `gable`) и `plan` с расчётами.
2. **Самокоррекция.** Валидатор возвращает модели список несоответствий, модель присылает исправленную сцену (по умолчанию 1 раунд).
3. **Изменение ТЗ.** Нужно пристроить гараж и при этом ничего не сломать.
4. **Зрение** (`--vision`). Два рендера эталонного дома, задача — посчитать окна и найти отличия.

Рендерер свой, на numpy: z-буфер, тени, контуры. Работает без GPU и OpenGL.

## Быстрый старт

```bash
pip install -e ".[mp4]"          # numpy, Pillow, requests (+ imageio-ffmpeg для MP4)
python -m qbench demo            # демо на mock-модели, без API
```

Прогон настоящей модели через любой OpenAI-совместимый API (по умолчанию OpenRouter):

```bash
export OPENROUTER_API_KEY=...
python -m qbench run --model <provider>/<model> --label "Моя модель" --vision
```

Другие провайдеры:

```bash
# OpenAI напрямую
python -m qbench run --model <model> --base-url https://api.openai.com/v1 --api-key-env OPENAI_API_KEY
# локально: Ollama / vLLM / LM Studio
python -m qbench run --model qwen2.5:14b --base-url http://localhost:11434/v1 --max-tokens 0
# параметры рассуждения и прочее — как есть в тело запроса
python -m qbench run --model <model> --extra '{"reasoning": {"effort": "high"}}'
```

Результаты появляются в `results/<модель>/<время>/`:

| Файл | Что это |
|---|---|
| `video.gif`, `video.mp4` | ролик |
| `poster.png`, `scorecard.png` | кадр дома и карточка итогов |
| `report.md` | все проверки с диагностикой |
| `run.json` | сырые данные прогона |
| `scene_*.json` | сцены по фазам |
| `responses/` | ответы модели |

`results/LEADERBOARD.md` обновляется автоматически.

### Ручной режим (модель без API, чат-интерфейс, агент)

```bash
python -m qbench run --model my-model --label "Модель X" --manual results/model-x/run1 --vision
```

Бенчмарк пишет промпт в `results/model-x/run1/dialog/01_build.prompt.md` и останавливается. Отдайте промпт модели и сохраните её ответ рядом как `01_build.response.md`, затем запустите ту же команду снова. Прогон воспроизведёт пройденные шаги и выдаст следующий промпт. Промпты фаз 2 и 3 — продолжение того же диалога.

### Прочие команды

```bash
python -m qbench prompt                              # текст задания
python -m qbench validate scene.json                 # проверить сцену или ответ модели
python -m qbench validate garage.json --prev base.json
python -m qbench render scene.json -o house.png
python -m qbench video results/<модель>/<время>      # перерендерить ролик
python -m qbench leaderboard
```

Качество видео задаётся флагом `--quality fast|normal|high` (480×360, 640×480, 960×720). Рендер ролика на 2 ядрах занимает 1–3 минуты.

## Устройство

```
qbench/
  prompts.py      задания всех фаз
  scene.py        DSL сцены, разбор ответа, геометрия примитивов
  checks.py       проверки, веса, способности, агрегация
  runner.py       фазы прогона, отчёт, лидерборд
  llm.py          OpenAI-совместимый клиент, ручной режим, mock
  vision.py       визуальный тест
  reference.py    эталонный дом (проходит 100%) и «испорченная» версия
  render/         растеризатор, карточки, сборка видео
tests/
```

Эталон из `reference.py` проходит все проверки. Это гарантирует, что задача решаема и валидатор согласован с ТЗ. Тесты проверяются командой `python -m pytest`.
